# DESIGN.md — 시각 SSOT

| 항목 | 내용 |
| --- | --- |
| 역할 | 색·활자·간격·컴포넌트의 단일 기준. 코드·운영 기준은 `CLAUDE.md` |
| 구현 | `src/app/globals.css`의 `@theme` 블록 |
| 방향 | 감사 보고서 |
| 화면 설계 | Claude Design 캔버스 (`design/*.dc.html`) |

---

## 1. 방향

이 서비스는 회사 자료를 읽어 IR 발표자료를 만든다. 사용자가 결과를 신뢰할 수 있는지는 **어디까지가 자료에 적힌 사실이고 어디부터가 분석과 가정인지** 화면이 정직하게 말해주는지에 달려 있다. 그래서 시각 언어를 **법률·회계 검토 문서**에서 가져왔다. 절제, 정확, 넉넉한 여백. 설득하지 않고 보여준다.

PRD §12.1의 "차분한 작업 도구"를 따르되, 색 팔레트와 구조는 새로 잡았다. PRD가 예로 든 오프화이트(`#F6F7F4`) + 네이비 조합은 도구형 SaaS의 기본값이라 이 제품의 성격을 담지 못한다.

**웹과 슬라이드는 다른 팔레트를 쓴다.** 웹은 종이·잉크 계열로 물러나 있고, 결과 화면의 슬라이드 지면 안쪽만 IR 자료의 색(네이비·그린·옐로, `AGENTS.md` §9)을 쓴다. PRD §12.1이 요구한 "PPT의 색이 웹의 정보 계층을 방해하지 않게"를 지면 경계로 지킨 것이다.

## 2. 핵심 장치 — 방주 색단

본문 왼쪽에 **92px 색단**을 두고 각 내용의 근거 등급을 표시한다. 학술·법률 문서의 방주와 각주 전통을 그대로 가져왔다.

```
┌──────────┬──────────────────────────────────────┐
│  92px    │  본문 (최대 62ch)                     │
│          │                                      │
│   사실 ⌐ │  2024년 매출 17억원, 전년 대비 62%¹   │
│   해석 ⌐ │  편의점 입점이 성장이 달라진 지점²³   │
│   추정 ⌐ │  3~5년 시나리오를 3개 구간으로 ▨▨▨   │
│   [  ] ⌐ │  해외 상시 유통을 확인할 자료가 없음  │
└──────────┴──────────────────────────────────────┘
```

| 등급 | 색단 표시 | 본문 처리 | 뜻 |
| --- | --- | --- | --- |
| 사실 | `사실` (중간 잉크, 500) | 각주 번호 | 자료에 직접 적혀 있음 |
| 해석 | `해석` (연한 잉크) | 각주 번호 여러 개 + 분석 설명 | 여러 자료를 이어 붙인 분석 |
| 추정 | `추정` (연한 잉크) | 사선 배경 + 면책 문구 | 가정이 들어간 전망 |
| 확인 필요 | `수치 상충` (경고색, 500) | 값 나란히 비교 | 자료 간 값이 다름 |
| 자료 부족 | `[ ]` (등폭) | 부족한 정보명 + 추가 방법 | 확인할 자료가 없음 |

**등급을 색으로만 구분하지 않는다.** 위치(색단)와 활자(자간·굵기·등폭)와 배경 패턴이 1차 신호이고, 색은 보조다. 이 구조 덕에 접근성 요건 A11Y-009(상태를 색상만으로 구분하지 않음)가 설계 단계에서 충족된다.

색단 폭 `--gutter: 92px`가 바뀌면 전 화면 정렬이 깨진다. 바꿀 때는 5개 화면을 모두 다시 본다.

## 3. 색

`oklch`로 정의한다. 명도·채도를 눈으로 비교할 수 있어 계층을 만들 때 유리하다.

### 3.1 지면과 잉크

| 토큰 | 값 | hex | 종이 대비 | 용도 |
| --- | --- | --- | --- | --- |
| `--color-paper` | `oklch(0.985 0.003 85)` | `#FBFAF8` | — | 전체 배경 |
| `--color-surface` | `oklch(1 0 0)` | `#FFFFFF` | — | 상단바, 표, 패널 |
| `--color-ink` | `oklch(0.24 0.015 265)` | `#1C1F27` | **15.76:1** | 본문, 제목 |
| `--color-ink-muted` | `oklch(0.44 0.012 265)` | `#4F5359` | **7.44:1** | 설명, 보조 문장 |
| `--color-ink-faint` | `oklch(0.55 0.011 265)` | `#6E7278` | **4.65:1** | 라벨, 캡션, 메타 |

`--color-ink-faint`는 **AA 하한(4.5:1)에 붙어 있다.** 더 밝히면 위반이다. 이 값은 처음 `0.68`로 잡았다가 2.88:1로 미달해 내린 것이고, 정보 전달용 텍스트에 쓰이므로 장식 예외를 적용할 수 없다.

### 3.2 괘선

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-rule` | `oklch(0.89 0.006 265)` | 구획 경계, 입력 테두리 |
| `--color-rule-soft` | `oklch(0.94 0.004 265)` | 표의 행 구분 |

괘선은 텍스트가 아니므로 대비 하한을 적용하지 않는다. 다만 괘선만으로 정보를 나르지 않는다.

### 3.3 검인과 상태

| 토큰 | 값 | 종이 대비 | 용도 |
| --- | --- | --- | --- |
| `--color-seal` | `oklch(0.45 0.15 22)` | 7.71:1 | 주요 행동 버튼, 각주 번호, 현재 단계 |
| `--color-seal-deep` | `oklch(0.36 0.15 22)` | — | hover |
| `--color-warn` | `oklch(0.55 0.11 70)` | 4.76:1 | 자료 부족, 수치 상충 |
| `--color-danger` | `oklch(0.52 0.17 27)` | — | 읽기 실패, 삭제 |
| `--color-ok` | `oklch(0.45 0.09 155)` | 6.81:1 | 읽기 완료, 단계 완료 |
| `--color-focus` | `oklch(0.52 0.16 258)` | — | 키보드 포커스 |

**색은 세 곳에만 쓴다**: 검인(주요 행동과 각주), 상태 표시, 오류. 그 밖의 강조는 활자와 여백으로 한다.

포커스는 검인과 다른 계열(청색)이다. 검인색을 포커스에 재사용하면 "누를 수 있는 것"과 "지금 선택된 것"이 섞인다.

### 3.4 다크 모드는 두지 않는다

PRD에 요구가 없고, 종이·잉크 은유가 반전되면 감사 문서의 성격이 사라진다. 스캐폴딩의 `prefers-color-scheme` 블록은 제거했다. 필요해지면 별도 결정으로 다룬다.

## 4. 활자

| 역할 | 서체 | 이유 |
| --- | --- | --- |
| 본문·UI | **IBM Plex Sans KR** | 한글·영문이 한 패밀리로 안정적이고, 숫자 판별이 좋다. 기본값 서체(Inter·Roboto·Arial)를 피한다 |
| 숫자·파일 위치 | **IBM Plex Mono** | 표에서 자리폭이 흔들리지 않는다. 같은 패밀리라 함께 써도 어색하지 않다 |

세리프는 쓰지 않는다. 도구 UI에 문서다움을 넣는 역할은 방주 구조와 괘선이 이미 하고 있다.

### 4.1 램프

하한은 PRD §12.3을 따른다.

| 토큰 | px | 행간 | 용도 |
| --- | --- | --- | --- |
| `--text-note` | 12 | 1.5 | 각주, 캡션, 방주 라벨 |
| `--text-small` | 14 | 1.6 | 보조 본문 (PRD 하한) |
| `--text-body` | 16 | 1.65 | 기본 본문 (PRD 하한) |
| `--text-lead` | 18 | 1.6 | 도입 문단 |
| `--text-section` | 20 | 1.4 | 섹션 제목 |
| `--text-title` | 28 | 1.28 | 페이지 제목 (PRD 하한) |
| `--text-figure` | 34 | 1.15 | 큰 수치 |

각주 상첨자만 11px을 쓴다. 검인색이라 대비가 7.71:1이고, 상첨자 번호는 본문이 아니라 위치 표시자다.

한글은 라틴보다 행간이 더 필요해 본문을 1.65로 잡았다. PRD 하한 1.45보다 넉넉하다.

### 4.2 하지 않는 것

- 영문 라벨을 대문자로 늘려 쓰지 않는다 (`OVERVIEW`, `STATUS`)
- 제목에서 한 단어만 색이나 굵기로 강조하지 않는다
- 버튼 문구 끝에 화살표(`→`)를 붙이지 않는다
- 메타 정보를 중간점으로 이어 붙이지 않는다 (`A · B · C`). 세로 괘선이나 표를 쓴다
- 본문 줄길이는 80자 미만으로 유지한다 (`--container-read: 62ch`)

## 5. 간격과 폭

- 격자 단위 `--spacing: 4px`
- 주요 작업 영역 `--container-work: 1200px`
- 결과 화면 `--container-wide: 1440px`
- 읽는 문단 `--container-read: 62ch`
- 섹션 사이 32px 이상 (PRD §12.4)

한 화면에 같은 무게의 버튼을 여러 개 두지 않는다. 주요 행동은 검인색 하나, 나머지는 테두리만 있는 버튼이나 문구 버튼이다.

## 6. 컴포넌트 규칙

### 6.1 카드를 쓰지 않는다

목록과 데이터는 **표와 괘선**으로 만든다. 같은 모양의 둥근 카드에 내용을 담고 그림자를 깔면 계층 정보가 사라지고, 문서의 성격과도 어긋난다.

테두리 반경은 기본 `0`이다. 곡률을 쓰려면 왜 필요한지 이 문서에 근거를 남긴다.

### 6.2 상태 표시

상태는 **아이콘(인라인 SVG) + 텍스트 라벨**을 함께 쓴다. 아이콘만, 색만으로는 표시하지 않는다.

| 상태 | 표시 |
| --- | --- |
| 준비 중 | 시계 · 연한 잉크 |
| 처리 중 | 부분 원호 · 검인색 |
| 완료 | 체크 · 완료색 |
| 확인 필요 | 삼각 경고 · 경고색 |
| 삭제 중 | 시계 · 연한 잉크 |

서버 상태 Enum 9종을 사용자에게 5종으로 보여준다. 세부 단계는 진행 화면에서만 펼친다.

### 6.3 아이콘

인라인 SVG만 쓴다. 이모지와 아이콘 폰트는 쓰지 않는다. 20px 격자, `stroke-width: 1.8`, 획 기반 한 가지 양식으로 통일한다.

### 6.4 진행률

**백엔드가 완료한 단계만** 반영한다 (PRD §5.3). 시간 경과로 올라가는 가짜 애니메이션을 넣지 않는다. 값이 그대로여도 현재 단계 설명과 완료한 작업 목록을 보여준다.

## 7. 접근성 (WCAG 2.2 AA)

설계로 이미 담보한 것.

| 요건 | 어떻게 |
| --- | --- |
| A11Y-002 포커스 표시 | `:focus-visible`에 2px 외곽선 + 2px 여백, 전역 |
| A11Y-003 본문 대비 4.5:1 | 잉크 3단계 모두 계산해 통과 확인. §3.1에 수치 기록 |
| A11Y-009 색상 단독 구분 금지 | 근거 등급은 방주 위치와 활자로, 상태는 아이콘+라벨로 |
| A11Y-010 모션 감소 | `prefers-reduced-motion`에서 전역 차단 |

구현 단계에서 지켜야 할 것: 키보드 전체 흐름(A11Y-001), `aria-live` 단계 알림(A11Y-006), 오류와 필드의 프로그램적 연결(A11Y-007), 썸네일 대체 텍스트(A11Y-008), 다이얼로그 포커스 트랩(A11Y-011·012).

**색 토큰을 바꿀 때는 대비를 다시 계산한다.** 눈대중으로 판단하지 않는다.

## 8. 캔버스와의 차이

`design/*.dc.html` 캔버스는 램프를 굳히기 전에 그린 것이라 본문 15px, 페이지 제목 26px을 썼다. 이 문서의 램프는 PRD §12.3 하한을 따라 **본문 16px, 제목 28px**이다.

구현은 이 문서를 따른다. 캔버스는 다음 수정 때 램프에 맞춘다.

## 9. 바꿀 때
